# Decisions
- D1: Working folder is C:\Projects\Platera (provided by user). .NET SDK 10.0.400 pinned in global.json.
- D2: Layout: src/ (Domain, Application, Infrastructure, Api), tests/Platera.Tests, web/ (Angular 22).
- D3: DB: (localdb)\MSSQLLocalDB with Trusted_Connection; no passwords committed.
- D4: EF Core/Identity/JwtBearer pinned to 10.0.11 (latest NuGet is 11.x preview-line targeting net11; net10 SDK in use). dotnet-ef 11 global tool works with it.
- D5: AppUser/AppRole live in Platera.Domain (inherit Identity base classes via Microsoft.Extensions.Identity.Stores) so entities can navigate to authors; Application depends on EF Core through IApplicationDbContext.
- D6: Dropped Microsoft.AspNetCore.OpenApi in favour of Swashbuckle (JWT-aware Swagger UI); avoids Microsoft.OpenApi version conflict.
- D7: Dev admin password lives in appsettings.Development.json (dev-only, documented in README per the brief); production must supply Seed:AdminPassword via user-secrets/env. Admin is NOT seeded when no password is configured.
- D8: Seed images are original SVGs generated by tools/gen-seed-images.mjs into src/Platera.Api/wwwroot/seed.
- D9: Migrations applied on startup (Database:MigrateOnStartup), seeded by DbSeeder.
- D10: JWT access token 15 min + rotating hashed (SHA-256) refresh tokens (14 days) stored in DB. Jwt:Key must be supplied (>=32 chars); a dev-only key lives in appsettings.Development.json; production uses user-secrets/env.
- D11: Rate limiting: built-in fixed-window limiter wrapped in AddPlateraRateLimiting (per IP+path), policies "auth" and "feedback", limits configurable.
- D12: Validation via FluentValidation executed by a global action filter; exceptions mapped to ProblemDetails by ExceptionHandlingMiddleware. Manual DTO mapping (no AutoMapper).
- D13: Integration tests use WebApplicationFactory + EF InMemory provider.
- D14: Recipe list/search/filter/sort and featured/trending are implemented in RecipeService (M4) so the browse UI can be built against them; likes/ratings/comments endpoints follow in M5. Trending = likes + visible comments in the last 7 days.
- D15: Image uploads validated by magic bytes (JPEG/PNG/GIF/WebP), max 5 MB, stored via IImageStorage (LocalImageStorage under wwwroot/uploads, gitignored). Recipe image URLs must be /uploads/* or /seed/*. Images deleted from disk when removed from a recipe or the recipe is deleted.
- D16: Admins may edit/delete any recipe ("full privileges"); regular users only their own.
- D17: Admin API (dashboard, users, featured, comment moderation, lookups) shipped with M5 so the M7 admin UI has endpoints. Deactivating a user revokes refresh tokens and blocks login; an already-issued 15-minute access token stays valid until expiry (accepted trade-off, short lifetime).
- D18: Hidden comments are visible only to admins; users can delete their own comments, admins any.
- D19: Frontend is Angular 22 (standalone, signals, OnPush, lazy routes) with a custom SCSS design system (no Material): terracotta/olive on cream, Fraunces serif headings, dark mode via data-theme + CSS variables, WCAG-AA-checked primary colours.
- D20: Dev server proxies /api, /seed and /uploads to the API (web/proxy.conf.json, port 5283) so the SPA uses same-origin relative URLs; production should do the same behind a reverse proxy.
- D21: Tokens are kept in localStorage (access + refresh) with single-flight refresh in the HTTP interceptor. Trade-off vs httpOnly cookies noted; acceptable for this app's scope.
